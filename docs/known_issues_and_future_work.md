# Known Issues And Future Work

This document tracks known limitations and later-stage work. These are not blockers for the current stable single-report workflow, but they should guide future improvements.

## Real Experiment Software Execution (Roadmap)

The default `execution_mode: synthetic` is a configuration placeholder for the current workflow. It does not launch or operate experiment software. Current runs prepare report content and use the selected image source; real application execution and capture are not implemented.

We plan to continue updating the skill toward a real execution interface with software-specific adapters, controlled experiment steps, and real evidence capture. This is a future roadmap commitment without a release date. Until implemented and tested for a specific application, do not describe the skill as able to run that application or produce real captures automatically.

## Formal Experiment Type Recognition

Formal experiment type recognition must not depend only on smoke-test hook phrases such as `本实验应识别为 network_hcl`.

Detection should prioritize natural report evidence:

- experiment environment,
- experiment platform,
- software used,
- lab tools,
- development environment,
- course name,
- experiment name,
- experiment content.

The resolved experiment type must never remain `auto`.

## DataGrip Full Report Smoke

The DataGrip database workflow still needs a dedicated full-report smoke test.

Areas to verify:

- DataGrip profile selection.
- SQL editor screenshots.
- Database tree and result-grid screenshots.
- Avoiding HCL reference pollution in database prompts.
- Long SQL text fills and result explanations.

## Long Text Blocks

Long generated text insertion needs further design and testing for:

- experiment summaries,
- experiment result analysis,
- thinking questions,
- multi-step code with explanation,
- paragraph style preservation,
- multi-paragraph insertion without damaging template layout.

## Table-Cell Internal Anchors

Table-cell image insertion is stable for simple table cells and append-to-cell cases.

Still needs targeted testing:

- inserting after a specific paragraph inside a table cell,
- replacing only a blank paragraph inside a populated cell,
- preserving surrounding table-cell text.

## Batch Identity Replacement

Batch identity replacement remains a later capability.

Requirements before enabling:

- explicit identity anchors,
- roster or field-map configuration,
- no broad full-document replacement,
- tests proving class, student ID, and student name do not leak into screenshots or filenames unintentionally.

## Screenshot Watermark Strategy

Screenshot watermarking needs later design.

Questions:

- whether a student ID watermark is required,
- whether the watermark should be generated by the image prompt,
- whether scripts should overlay the watermark after generation,
- whether watermarking should remain disabled by default.

Default policy for now: identity-derived watermarking is disabled unless explicitly requested and safely configured.
